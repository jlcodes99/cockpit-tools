# 本地数据查询与迁移实现说明

规范见 [查询字段与无感数据迁移规则](query-and-migration-rules.md)。本文记录此次性能治理的实现边界与回归检查点，不是发布操作指南。

## 查询路径

| 场景 | 新读取路径 | 写入与历史处理 |
| --- | --- | --- |
| Kiro / Windsurf 账号列表 | 只读取账号，不在列表调用中去重 | 后台身份快照回填、按身份分桶查找重复；版本完成后停止去重 |
| Kiro / Windsurf / Trae 添加、更新匹配 | 优先读取索引中的版本化身份快照，仅未回填记录回退读详情 | 所有宿主详情保存入口先失效变化的身份投影，再保存详情与摘要；后台 CAS 写回不能覆盖更新、删除 |
| 请求日志会话筛选 | 可索引的 `effective_session_id` 映射 → request ID 索引 | 诊断写入、更新、删除由同事务触发器维护；历史每批最多 32 条；未完成时只扫描受限保留的诊断表，不逐条探测全部日志 |
| 请求日志实例筛选 | 等值匹配实例 ID | 使用现有实例/时间索引；账号和 API Key 的精确 ID 参数与自由文本搜索参数分离 |
| Codex 会话用量同步 | 文件未变化跳过；追加从字节检查点继续 | 持久化模型、累计 token 高水位、快照签名、事件编号、分叉匹配位置和未完整写入的尾部状态 |
| 父会话回放去重 | 宿主库中按文件、代次、签名、行号查询 | 父 JSONL 分批解析，不保留全历史内存数组；官方日志只读 |
| API / 会话用量统计 | UTC 分钟汇总 + 时间范围边界明细 | 新增、更新、历史价格重算、删除均由源表触发器增减；成员表避免回填与实时写入重复累计 |

会话 ID 仍遵守“已采集 thread ID 优先，否则 session ID”规则；未采集的数据保持未知。诊断清理会同步清理映射，保留原有诊断保留期语义。

## 资源控制

- 自动维护共享单工作线程与资源许可，队列最多 16 个不同任务，同一任务去重。
- 默认每批最多 32 条、2 MiB 输入，协作式 CPU 时间预算 25ms，批次间至少休息 150ms；SQL 回填另有执行中断预算。
- 锁争用不等待：`try_lock` 失败先让路；SQLite 后台锁等待为 10ms。文件读取/解密在批次内执行，不能保证单次系统调用的墙钟耗时小于预算，但不在主线程或异步执行线程同步等待。
- 账号详情超出单条维护字节预算时保留原文件，不伪造身份，不清空账号；记录维护失败供后续排查。
- 分批失败最多连续重试 5 次并退避；后续访问可重新调度，持久化游标或记录版本保留已完成进度。
- 查询并发最多 2 个，前端统计修订采样与输入防抖抑制密集重查。运行中的物理查询仍持有并发许可，调用方离开页面不会释放许可后启动无限新任务。

资源预算是限制并发、输入规模与持续占用的机制，不是对所有硬件承诺固定 CPU 百分比或零磁盘开销。不得为了追求升级速度扩大批次或取消批间让步。

## 数据安全与一致性

- 身份索引不存明文凭据；只保存平台身份字段和凭据摘要。旧数据缺字段只针对未回填记录兼容，完成后直接使用新快照。
- 自动去重先保存合并结果和重复详情的原格式备份，再更新索引，最后按原文件哈希清理重复详情；加密文件的备份仍为密文，历史明文文件不会被冒称为加密备份。保留已绑定账号 ID；两个账号都被实例绑定时不自动删除其中任一个。
- 已提交解析事件与解析检查点在同一事务中更新；半条 JSONL 不推进检查点。超长非用量消息分段跳过，超长用量记录显式报错，不静默生成错误计费。
- 文件被截断或重写时，旧数值快照分批备份，重建期间仍供报表查询。替换解析全部完成才切换可见结果；中断后保留旧结果并从持久化进度恢复。
- 汇总未完成时只合并尚未入桶的源记录，使用同一个读事务快照，避免迁移推进与查询交错导致漏计/重复。已完成后移除该兼容扫描。
- 汇总按 UTC 分钟存储，按当前本地时区展示；时区变化不需重新清洗所有明细。时间范围两端不足完整分钟的部分继续精确读取明细。
- 价格变更维护汇总金额；消费预算结算是独立业务数据，不因历史价格重算而改变。

## 复审与验证清单

1. 旧摘要缺字段、身份冲突、同邮箱不同用户、不同 API Key 与不同 Trae 平台。
2. 一万个不同身份的分批扫描不产生两两比较；记录版本与索引修订变化使扫描重新校验。
3. 回填期间更新、删除、源文件变化，CAS 不能覆盖新版本或复活已删除文件。
4. 会话筛选查询计划使用会话映射索引和 request ID 索引，不出现逐日志行的关联子查询。
5. JSONL 追加、未写完尾部、跨批次累计用量、分叉签名跳跃匹配及进程重启恢复。
6. 汇总回填与实时更新交错、金额重算、清空、ID 复用、时间边界、事务回滚及文件重写的旧快照保留。
7. 仅使用临时目录和合成数据进行代码级验证，不启动 GUI、不读写真实账号库、不执行正式数据清洗脚本。

## 本轮验证记录

- 性能治理针对性 Rust 回归 39 项通过，覆盖身份快照、CAS、查询计划、回填、价格变更、清空、检查点和文件截断后再次追加。
- 请求日志前端测试 11 项通过；类型检查、翻译键/值复用检查、差异空白检查通过。
- 完整 Rust 单线程测试：4356 项通过、1 项失败、35 项忽略。失败项为未修改模块中的 `codex_wakeup::tests::runtime_candidate_probe_rejects_existing_but_unusable_launcher`，单独精确复跑通过；完整测试仍不能记为全绿，失败原因未在本轮归因。
- 未执行 GUI 验证、真实用户数据迁移、提交或发布。迁移实际运行在用户启动升级后的宿主并访问对应数据时，正常情况下不需要手工操作。
