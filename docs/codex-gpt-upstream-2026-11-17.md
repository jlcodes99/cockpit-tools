2. **补齐 WS 包装状态和重试提示的协议回归。** CPA 会从顶层、`body`、`error`、`body.error` 和 `response.error` 识别 `status` / `status_code`，并保留常见 429、超时、上游拥塞错误的嵌套 `Retry-After`。Cockpit 的兼容流错误解析缺少 `body.status` 和 `body.error.status` 等入口，已能读取多个位置的头对象和结构化延迟值。先补状态入口并验证 `body.error.headers` 以及显式状态、推断状态、外层空值与真实嵌套值的组合，再针对实证差异修改头解析。请求级错误、模型级拥塞和账号配额应继续各自处理。 [CPA WS 状态结构](https://github.com/router-for-me/CLIProxyAPI/commit/5a373ed) · [推断状态](https://github.com/router-for-me/CLIProxyAPI/commit/7dd360d) · [拥塞与嵌套头](https://github.com/router-for-me/CLIProxyAPI/commit/deacbf2) · [Cockpit 上游错误](../src-tauri/src/modules/codex_native_api/upstream_errors.rs#L312) · [Cockpit 重试提示](../src-tauri/src/modules/codex_native_api/events.rs#L1007) · [Sub2API 模型级拥塞 #8579](https://github.com/Wei-Shaw/sub2api/pull/8579)
3. **补 Claude ToolSearch 到 GPT 的协议回归。** CPA 在 Claude→Codex 转译中，把已发现工具的引用和声明放回历史对应位置，保持顶层工具表和早期 prompt cache 前缀稳定。Cockpit 当前 Claude 输入转译可解析 `tool_use` 与文本、图片、文档类 `tool_result`，Rust 原生包内未找到 `tool_reference` 或 `tool_search_tool_result` 支持。先用实际协议形状验证首轮搜索、次轮工具调用和再续接，检查顶层工具表、调用 ID、声明顺序和缓存前缀。该缺口与现有问题的因果关系仍需通过样本确认。 [CPA ToolSearch 提交](https://github.com/router-for-me/CLIProxyAPI/commit/374056f) · [Cockpit Claude 兼容转译](../src-tauri/src/modules/codex_native_api/compat_request.rs#L194)

## 本轮无需同步

- **Terra、Ultra Fast 和分组能力。** Sub2API 的 Terra 官方 Codex 清单使用 500k 默认窗口，客户端能力为 `low` 至 `ultra`，公有 API 允许 `none` 并拒绝 `minimal`，API Key 目录不宣告 Responses Lite。其订阅按实际发往的 Sol/Terra 模型免长上下文附加费。Cockpit 已固定 Terra 官方目录来源，并已有 Astra/Sol 的 Ultra Fast 目录限制和 6 倍计价。Sub2API 新功能是分组强制 `service_tier`，最终模型支持时 `ultrafast` 优先，其后是分组 `priority` 和客户端值。仅在 Cockpit 有明确分组自动改写需求时引入。另有显式启用的透传模型白名单，只使用映射源键筛选且空表允许，实际透传请求仍保留原模型。Cockpit 应沿用自身 API key 与来源模型范围。 [Terra #8365](https://github.com/Wei-Shaw/sub2api/pull/8365) · [Ultra Fast #8812](https://github.com/Wei-Shaw/sub2api/pull/8812) · [透传白名单 #8748](https://github.com/Wei-Shaw/sub2api/pull/8748) · [Cockpit Terra 目录来源](../src-tauri/src/modules/codex_model_catalog.rs#L21) · [Cockpit 目录用例](../src-tauri/src/modules/codex_protocol.rs#L3053) · [Cockpit 价格](../src-tauri/src/modules/codex_local_access_routing_pricing.rs#L1605)
- **Codex 分叉缓存。** Sub2API 把显式 `prompt_cache_key` 与原有 session 头或 body session 对齐，子会话仍保留自己的逻辑身份，并维持凭据/API key 隔离。Cockpit 的同一调用者、同一所有者内已共享映射，现有用例覆盖父会话、子会话、孙会话，以及独立的逻辑 session 与 cache alias。保留当前机制。 [Sub2API #8664](https://github.com/Wei-Shaw/sub2api/pull/8664) · [Cockpit 作用域映射](../src-tauri/src/modules/codex_native_api/identity.rs#L1376) · [Cockpit 分叉回归](../src-tauri/src/modules/codex_native_api/identity_tests.rs#L253)
- **云网关架构和计费策略。** CPA 的调度连续性 hook 是可选插件 RPC，宿主限制等待总预算，适用于调度前和输出前 429。Cockpit 使用自己的本地恢复策略。Sub2API 的扣费合批、调度快照合并、分组强制 tier 和 CPA 的 YAML 请求内容改写属于各自的部署与配置。Cockpit 当前的请求级目录快照和 TLS 根证书复用位于本地链路，现有证据不足以将 tok/s 变化归因于上游调度。缓存写入 TTL 可在 Cockpit 取得可信的上游细分用量时再独立核对。 [CPA 调度 hook](https://github.com/router-for-me/CLIProxyAPI/commit/7fcdfcf) · [CPA payload #7605](https://github.com/router-for-me/CLIProxyAPI/pull/7605) · [Sub2API 调度 #8833](https://github.com/Wei-Shaw/sub2api/pull/8833) · [Sub2API 扣费 #8816](https://github.com/Wei-Shaw/sub2api/pull/8816) · [Sub2API 缓存写入 TTL #8606](https://github.com/Wei-Shaw/sub2api/pull/8606) · [Cockpit 目录](../src-tauri/src/modules/codex_local_access_native_routes.rs#L1020) · [Cockpit TLS](../src-tauri/src/modules/codex_local_access_native_transport.rs#L447) · [Cockpit 缓存写入计价](../src-tauri/src/modules/codex_local_access_routing_pricing.rs#L2047)
