# Antigravity 按账号选择代理节点

日期：2026-11-28
状态：方案已选择，设计待用户确认

## 意图

用户要的是 Codex 那种从订阅/节点资源选择出口的体验，而不是只有手填 URL。用户已选择「与 Codex 共用资源目录和引擎、账号绑定独立」方案，要求完成验证后直接提交 PR。旧 PR #3335 当前已关闭且未合并，需新建 PR，而非宣称已更新旧 PR。

## 目标

1. Antigravity 账号卡片的代理入口打开与 Codex 一致的来源、分组/策略、节点选择器，复用其筛选、延迟徽章、测速、错误提示与引擎安装引导。
2. 两个平台共用现有加密资源目录，不复制订阅。账号绑定按平台隔离，选择 Antigravity 节点不修改 Codex 绑定。
3. 覆盖 Antigravity CLI、IDE、legacy、受管实例及切号后的启动；绑定节点时启动环境指向账号稳定的 loopback 入口，而非短命引擎端口。
4. 已接入入口的进程换节点后，新连接使用已保存的新出口，旧连接持有旧引擎租约至结束。首次由原生网络/旧 URL 切到节点入口需重新启动客户端。
5. 引擎、账号、资源或绑定无效时明确失败，不静默直连或任意挑另一个节点。
6. 保留旧版本手填 URL 的读取与使用兼容；保存新节点或恢复默认必须定义清晰且无隐藏旧值重新生效。

## 非目标和反目标

- 不复制整套 Codex 工作台：连接日志、流量图、国家守卫、API 服务、Codex 专属 Windows 启动策略不套到 Antigravity。
- 不自动改变已有 Codex 统一出口，也不把 Antigravity 凭据写入 Codex 账号库。
- 本次不改 Google OAuth 授权和 Token/额度请求的出口，仅管理客户端进程的出口。
- 不承诺已有长连接立刻迁移，不承诺 Cockpit 退出后托管引擎继续运行。
- 不覆盖现有 Gateway/Zcode 工作区、不导出真实账号/订阅/节点凭据、不为方便测试使用用户真实账户流量。

## 方案取舍

### A. 共用资源，独立绑定（用户已选择）

直接复用资源目录、绑定构建/校验、Mihomo 引擎和节点选择组件；Antigravity 的绑定和稳定入口有独立平台身份。维护一份订阅，不影响 Codex 账号选择。

### B. 独立资源目录（未选）

隔离简单，但需重复导入、更新和维护资源，不符合用户的一套体验目标。

### C. 只展示节点下拉、把引擎临时端口保存为 URL（排除）

界面改动少，但重启端口失效，且不能安全热切换，不满足真实节点绑定需求。

## UI 与交互

沿用账号卡片与列表的代理入口；弹窗复用 Codex 的样式、SingleSelectDropdown、CodexProxyPicker、useProxyLatency 和选择草稿辅助函数。不得把 Antigravity Account 强行塞进 Codex 前端账号 store。

```text
账号 A · 当前出口：订阅一 / 香港 01
  ○ 跟随全局设置
  ● 独立代理

  资源来源 [订阅一              v]
  策略组   [香港节点            v]
  节点     [香港 01 · 82 ms     v]

  [测速]                         [保存]
```

- 本设计中的「跟随全局设置」指设置→网络的现有全局代理，不是 Codex 专属统一出口。文案必须消除歧义。已有 Antigravity URL 版本的默认行为保持不变。
- 资源为空显示引导，并提供可达的现有资源管理入口；不创建第二套订阅管理器。
- 选中节点只改草稿，保存成功后更新卡片；取消不写入。切换账号、关闭弹窗时取消测速，过期异步回包不能修改新账号。
- 旧 URL 绑定显示脱敏的兼容状态，可改选资源节点或恢复默认；不得显示带密码的完整 URL。
- 无效资源显示失效状态，不自动选来源或节点作为替代出口。
- 保存时须防重复点击；失败保留草稿和原绑定，显示可本地化的固定错误，不透出订阅 URL、控制口令或节点密码。

## 数据与绑定

使用独立平台身份（例如 antigravity + account_id），复用现有资源 Reference 与 Binding 构建器。持久化节点引用至少包含 sourceId/itemId/groupId/selections；若保存凭据快照，必须走现有加密 secret 存储与原子写入，前端仅返回脱敏描述与引用。

实现者可选择独立加密路由存储或账号内隐藏字段，但需遵守：

1. 新字段/文件缺失时旧账号无损读取。
2. 不在账号返回对象、日志、命令行、Git 或明文端口注册文件返回 Binding envelope。
3. 变更受账号级串行化保护；校验引用与引擎准备后，按「持久化成功→运行时发布」提交。失败不改旧绑定。
4. 节点绑定优先于旧手填 URL；保存节点/恢复默认时清除相互冲突的旧状态，避免解绑后旧 URL 复活。
5. 不持久化临时引擎端口；稳定入口端口只保存账号平台身份和端口。
6. 共享资源删除预览列出 Codex 与 Antigravity 的全部引用者，并清楚提示这是全局资源操作。确认删除允许影响所有引用者：Codex 沿用原删除语义；Antigravity 将绑定标为失效并阻断新连接，不恢复旧 URL 或直连。所谓「独立绑定不影响 Codex」仅指单账号选择/解绑，不承诺删除共享资源无跨平台影响。
7. 订阅刷新保留 Antigravity 已保存的凭据快照与选中出口，不因参数/成员变化自动改选。刷新后来源/选中项不存在则将绑定标记失效并阻断新连接；仍存在时保持旧快照，用户重新选择并保存才应用新参数。策略组的运行时自动节点选择仍按保存时策略运行。此决定对齐 Codex 普通账号快照语义，不机械复用 client-proxy 的自动重绑定行为。
8. 账号主动恢复全局设置后，旧稳定入口拒绝新连接，已有连接自然排空；界面明确提示重新启动客户端，新进程才按当前全局设置启动。即使全局代理已关闭，也不能让仍挂旧入口的进程突然直连。

## 运行时

共享引擎与通用代理传输能力，但把平台账号解析与 Codex 账号策略分开。不复制整份 Codex 路由文件，也不全盘泛化现有 Codex 架构。本期采用独立加密 Antigravity binding store、保留前缀的运行时身份及窄范围解析分流；允许构造无令牌的私有内存路由投影以复用既有传输类型，绝不保存伪造 Codex 账号或触发其 Token/账号池逻辑。

平台解析器必须先验证 Antigravity 账号仍存在，显式解析其节点/旧 URL/全局回退；不得消费 Codex unified fallback、Codex direct-hosts 或 Codex 实例启动参数。现有 load/invalidation、资源消费者和删除 hook 必须认识平台身份。现有候选引擎 prepare/publish 流程可复用，持久化由 Antigravity 自己的锁与加密 store 承担。

- 入口仅监听 127.0.0.1，支持客户端实际消费的 HTTP CONNECT / SOCKS 语义；设置适当连接/握手/启动超时与并发上限。
- 每条新连接按当前账号的已保存绑定解析，使用与绑定签名匹配的引擎租约。
- 新引擎先准备好再替换旧引擎，已有连接持有 Arc/租约保活；新绑定不能误用旧引擎。
- 账号删除、新绑定失效、引擎退出时，新连接明确失败。旧入口不得被其它账号复用。
- 资源的自动策略保留原策略语义，不在前端将策略拍平成第一节点。
- 全局配置回退与旧 URL 兼容保持现有启动注入优先级。启动前解析/准备失败必须向上传递，不使用 .ok() 把错误吞成未配置。
- macOS open --env、Windows 命令、Unix env 前缀继续使用安全参数构造与转义。
- Cockpit 关闭时沿用统一引擎关闭机制。本期保证同一宿主进程内端口稳定、热换节点以及跨宿主启动的端口预约记录；不承诺自动扫描/接管宿主重启前已存在的 Antigravity CLI/桌面进程。宿主重启后需通过 Cockpit 重新启动对应客户端，以完成入口恢复。端口恢复失败明确提示，不悄悄换端口骗运行中的客户端。此边界在 UI 提示和 PR 中说明。

## 验收与测试

1. 前端：恢复保存草稿、来源/策略/节点选择、失效引用、取消不写、换账号晚到响应、失败保留旧值、空目录引导和隐私展示测试。
2. Rust：旧数据兼容、资源绑定校验、加密存储/脱敏返回、账号隔离、端口稳定、更新新连接且旧连接不中断、引擎/资源缺失 fail-closed、账号删除、资源删除依赖及并发保存测试。
3. 启动：CLI 和桌面各路径取得稳定入口，命令转义不回归；未配置节点的旧行为测试。
4. 构建：locale 全量一致性、TypeScript 检查、相关 TS 测试、前端生产构建、cargo check 和相关 Rust 测试；若主分支测试失败，依据具体复现证据报告，不以「没改该文件」推断无关。
5. 最终审查差异，核对无凭据、无无关 WIP/缓存；PR 正文包含能力、使用路径、测试结果和首次接入/生命周期边界。
