# 界面设计规范

## 界面布局与验收

适用于新增或调整的页面和组件。

1. **沿用现有视觉体系。** 优先复用项目内同类页面或组件的布局、排版和交互模式。相同层级的信息使用一致的字号、字重和间距，相同用途的控件使用一致的尺寸和状态样式。
2. **按任务组织信息。** 让用户能快速识别当前位置、需要处理的内容和下一步操作。相关内容放在一起，说明与错误靠近对应对象。同组内容保持对齐，组间留白体现层级。
3. **明确空间不足时的布局。** 根据内容的重要性决定哪些元素截断、换行、换列或滚动。长文本或数据量增加时，关键状态仍须可读，主要操作仍须可达。
4. **用代表性状态验收。** 根据改动范围检查常用尺寸和最小支持尺寸，并覆盖相关的长文本、长译文、空数据、加载、失败和大量数据场景。检查信息层级、对齐和留白，确认内容无重叠或溢出，操作可以完成。
5. **如实记录验证方式。** 获得用户明确授权后，用实际运行的界面核查视觉和交互。仅做代码或静态检查时，在交付说明中注明实机验证状态。

## 设置弹框

- 历史存储等次要的多字段管理操作使用独立弹框。主页面只保留入口，打开时保持原内容的位置。
- 按任务组织正文。开关和它控制的字段放在同一组，统一标签、控件高度、列宽和间距。顶部可展示记录数、占用空间等有用状态。主操作和取消固定在底部，删除等危险操作在独立区域先预览再确认。
- 使用项目现有组件、设计变量和交互状态。长名称优先省略，窄窗口按需要改为单列。评审正常宽度、长名称和长译文，并验证 600px 高度下正文可滚动，关闭、取消和保存始终可达。点击遮罩不能关闭弹框。

## 账号与订阅套餐

- 展示具体账号的表格、卡片、复选列表、下拉选项及收起后的已选值，都同时显示账号名称和订阅套餐标识。
- 同平台复用账号总览的套餐展示逻辑和样式，保持原始套餐名称、配色、描边、形状及用户所选样式一致。套餐未知时使用平台的未知态。「全部账号」等集合选项无需套餐标识。
- 长账号名先省略，确保套餐标识可读。新增或修改账号选择入口时，核对该平台其他入口里的同一账号是否展示一致。
