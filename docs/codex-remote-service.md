# Cockpit 远程服务与 Key 用量预算

## 使用方式

1. 电脑 A 在 API 服务页面开启局域网共享，并创建一个 Key。
2. 展开该 Key 的策略，可设置美元用量预算、一次性／每日／每周／每月周期，以及可选的每日上限、并发请求数、每日生图请求数。保留已有 Token 限额；多个限制同时配置时均生效。
3. 电脑 B 在 Cockpit Tools 中将 A 的地址和 Key 添加为普通 API Key 账号。后台识别成功后，账号展示为“Cockpit 网关”，采用独立背景和 Cockpit 标识。卡片只展示按 UTC 统计的今日消耗（价格估算）、今日请求和今日 Token；预算、能力与状态移入详情。
4. B 启动或重启对应 Codex 实例时，使用已发现的能力生成实例配置。使用实例网关时，图片请求继续转给 A，不需要把 A 的上游凭据导入 B。

识别与用量查询在后台执行。普通供应商不提供本协议时继续使用原有接入；远端离线时保留账号与上次成功的展示数据。可见账号页的远程用量每 30 秒刷新，客户端底部沿用现有额度刷新周期。

## 预算口径

- 美元表示按服务端计量价格折算的用量预算，不是充值余额，也不等于真实付款。
- 预算从此功能开始记录调用结算金额；不使用历史估算价值回填。修改预算或价格不会清零已结算计量。
- 价格采用每次请求结算时的服务端配置；后续历史价格重算只影响估算统计，不改变已扣预算。
- 周期按 UTC 日历计算，每周一开始新周，每月 1 日开始新月，不结转。
- 同一 Key 的所有设备共享预算，A 是唯一计量来源。Token 限额继续累计输入、输出 Token；周期金额预算与累计 Token 限额分别展示。
- 准入按已结算消耗检查。已有在途请求仍会结算，可能超出金额或图片请求上限；这不是严格预付费扣款系统。可使用并发上限控制在途数量。
- 配置金额限制时，没有计量价格的模型会被拒绝。上游缺少用量或计量价格的已执行请求会标记为未计量，界面提示，不能将这些请求解释成准确的零费用。
- 每日生图上限统计成功的独立图片生成／编辑请求，不是返回图片张数；一次请求生成多张仍计一次。Responses 内置生图的消耗按其实际返回的用量计入金额，不承诺独立图片请求次数覆盖所有内置工具调用。
- Key 使用计量独立持久化，恢复时与配置中的计量按最新周期、较大累计值合并，避免旧设置快照退回已用额度。

## 协议 v1

所有接口使用 `Authorization: Bearer <key>`。连接信息和用量只返回此 Key 的数据；新的统计、明细接口拒绝未知参数，客户端不能指定其他 Key。不提供远程管理权限或上游凭据。

### GET /v1/cockpit/connection

返回 `product: cockpit-tools`、`protocolVersion: 1`、稳定服务标识、服务名称、Key 名称、状态、可见模型、生图型号和能力，以及 Token 限额与预算快照。

`modelCatalog` 是 A 本地 API 服务模型目录的公开投影，包含授权模型的名称、排序、思考档位、上下文和输入能力；`catalogRevision` 是目录摘要。B 的账号目录、实例目录与模型接口使用此元数据，优先于旧账号中保存的模型列表；有模型前缀时保留前缀。目录不会下发指令、工具代码、路径或上游凭据。独立生图模型通过 `imageModels` 提供，不混入对话选择器。

`keyViewsVersion: 1` 表示支持下述会话视图。旧版 A 没有此字段时，B 保留原有连接能力，并在底部详情提示升级网关所在电脑的 Cockpit Tools。

预算快照的金额使用整数 `microusd`（1 USD = 1,000,000 microusd），时间使用 Unix 毫秒。包含当前周期已用／剩余、每日已用／剩余、下次重置、累计消耗、未计量请求数和每日图片请求数。

额度耗尽或 Key 停用时，持有有效 Key 的客户端仍可查询自己的状态；推理和生图准入仍检查启用状态、模型权限和额度。Key 被删除或轮换后，旧 Key 无法查询。

### GET /v1/cockpit/usage?range=all

`range` 支持 `day`、`week`、`month`、`all`，默认 `week`。沿用 A 本地统计日历窗口，返回此 Key 的请求、成功／失败、生图请求、Token、延迟和估算价值汇总。预算周期独立采用 UTC，不能使用统计窗口消耗计算预算剩余。

### GET /v1/cockpit/stats

`startAt`、`endAt` 使用 UTC Unix 毫秒、按整小时对齐，起始包含、结束不包含，每次最多 93 天；默认近 7 天。返回汇总、小时／日趋势、`firstRetainedAt`、`updatedAt` 和 `ready`。统计只包含网关仍保留的日志，不能替代预算的累计消耗。

### GET /v1/cockpit/requests

使用同一日期范围。`pageSize` 默认 30、最多 100，`beforeTime` 和 `beforeId` 为上一页返回的游标；不执行全量计数。可按公开请求模型 `model`、`success`、请求类型 `kind` 精确筛选。筛选只影响明细，不改变上方日期统计。返回的字段限于自身请求编号、时间、公开模型、结果、耗时、Token、估算金额与扣额状态；不返回账号 ID、邮箱、代理、上游模型、重试过程或原始错误／请求正文。

当前会话可以附带 `threadId`、`instanceId` 和可选的 `installationId`，均为等值筛选。安装标识需要同时提供会话和实例；不能通过参数指定别的 Key。耗时包含 `firstResponseMs` 和 `outputGenerationMs`，无法可靠推导的历史耗时保持空值。

`settlementStatus` 为 `settled`、`unmetered` 或 `unrecorded`。历史记录没有逐笔结算依据时保持 `unrecorded`，不根据估算费用伪造扣额。逐笔扣额独立于价格重算；日志删除会减少历史统计，预算累计值仍保留。

### GET /v1/cockpit/session

要求 `threadId`，客户端同时传入实际请求携带的 `instanceId` 和可选的 `installationId`。返回当前 Key 的最近会话模型、首响时间，以及输出速度和缓存命中率；`model`、`serviceTier` 只选择最新请求指标，不改变会话均值。速度与缓存口径复用 A 本地底部统计读取器，最多读取 256 条当前会话的写入时摘要；没有可靠的关联或计量数据时返回空值，不猜测上游账号或用总耗时估算生成速度。

底部的今日／本周统计采用同一个 Key 的 `/stats` UTC 数据，会话明细采用 `/requests`，与账号详情共用数据来源。远程“查看更多”在当前弹框分页，不跳转到 B 的本地日志；展示最多 200 条。旧版不支持、统计整理中和网络失败分别提示，短暂失败保留已验证快照。

### 性能与迁移

请求写入时增量更新 Key 的小时汇总，价格重算和日志删除同步调整汇总。旧日志使用宿主统一维护调度器，与账号迁移、日志分类清洗共享资源；每批最多 32 行、25 毫秒 SQL 预算，批间主动休息。仅投影固定数字和最多 256 字节的 Key ID，不读取请求正文或 JSON，单批投影不超过 12 KiB；异常超长 Key ID 保留原始行并记录跳过计数，不冒充零用量。迁移持久化算法版本、代次、游标、高水位和完成状态。新代次完成前保留旧汇总，前端显示整理状态并可保留上次完整快照；完成后后台分批清理旧代次。

清空日志与切换代次在同一 SQLite 操作中完成，重置序号或恢复后不会因旧游标漏算新行；清空、重算和新日志提交会使远程查询缓存失效。日志行、逐笔扣额和小时汇总在同一事务内提交或回滚。该事务不包含独立的累计预算快照文件；日志历史仍不能作为完整的预算账本。

日志使用单线程有界写入队列：最多 256 项、单条编码最多 128 KiB；每批最多 8 项、512 KiB，事务有 25 毫秒 SQL 预算。进行中的原生请求也限制为 256 个日志准入名额，避免大量请求在队列外堆积。队列满时有界异步等待；存储错误保留当前批次，短暂重试后进入低频恢复，并暂时返回 503 拒绝新请求，不静默丢弃已接收的批次。队列是内存缓冲，进程在落盘前被强制终止仍可能丢失未提交日志；不宣称具备崩溃安全的持久化 outbox。

读取使用独立只读连接，不经过运行态锁或数据库维护路径。趋势只聚合当前 Key 的小时汇总，日志命中既有 Key／时间索引并使用游标分页；查询有 2 秒 SQL 中断预算、最多两个并发、相同查询单飞和最多 128 项的 5 秒缓存。客户端只在详情挂载时查询历史，隐藏窗口停止轮询，失败可在详情内重试。

带实例和会话的明细页直接由现有会话摘要复合索引驱动，再按日志主键读取固定公开字段，避免扫描整个 Key 的日志。会话摘要随新请求维护，不等待历史统计迁移；旧记录缺少可靠身份时不伪造回填。底部速度查询在既有有界后台工作槽中执行；网络请求有 5 秒上限，不阻塞注入刷新或页面操作。

独立生图／改图请求与文本请求共用日志，列表显示明确的操作类型。会话关联优先使用请求自身的 thread 标识；只有 thread 缺失时才采用自身的 session UUID，不按最近活跃聊天猜测。旧摘要有可靠 session 标识时，使用带版本、游标和高水位的后台任务自动补齐：每批最多 32 行、25 毫秒，字段在 SQLite 内限制到 4096 字节，单批身份投影不超过约 258 KiB；不解析历史正文，不覆盖新身份，也不复活已删除记录。请求没有可验证会话／实例信息时，仅显示在“当前 Key”范围。

### 客户端适配

描述符按地址和 Key 的摘要隔离缓存，不保存原始 Key；鉴权请求不跟随重定向。发现接口有 4 秒总超时、响应大小上限与同一目标单飞。前端后台发现最多同时处理两个账号，不阻塞账号列表读取或首屏。

只有宿主识别的固定能力字段参与配置，不执行远端脚本或远端 UI。远程服务能力会写入 Codex 生图兼容配置；Key 约束始终由 A 再次校验。

经过 B 的实例专属网关时，只转发已鉴权的连接、用量、统计、明细和会话只读接口；使用配置中的 A 端 Key，不授予远程管理权限。B 保留客户端会话、实例与安装标识，A 记录后再执行上游身份转换；B 不重复做会话身份改写或识图路由。要启用完整模型目录和会话视图，A、B 均需升级，随后重启 B 的对应 Codex 实例以重新生成实例配置。
