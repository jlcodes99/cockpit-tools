# 查询字段与无感数据迁移规则（强制）

1、频繁查询、筛选、排序、身份匹配和统计依赖的业务属性，必须维护明确的业务字段、快照、索引或汇总；禁止长期通过全量文件扫描、反复解析 JSON、逐条加载详情、关联子查询或两两比较弥补数据建模缺失。合理且有索引的关联不在禁止范围，评审应以实际查询计划和复杂度为依据。
2、新增查询字段时，必须明确权威来源、未知值语义和字段版本，并同步覆盖新增、编辑、导入、删除、授权刷新、切号及其他相关状态流转；派生字段与源数据应原子更新或通过可恢复的持久化任务保持一致，禁止只回填历史数据而遗漏后续写入。
3、旧数据由应用自动清洗、回填和升级，不要求用户运行脚本、点击修复或等待启动迁移。只允许修改本项目拥有的数据；官方客户端数据需要加速时，在宿主维护独立索引或快照，禁止擅自扩展官方数据库结构。无法可靠推导的历史字段必须保持未知，不得伪造身份、状态、计费或授权信息；索引不得包含明文凭据。
4、迁移必须持久化版本、进度/游标和完成状态，幂等、可恢复、可重试；正常查询与迁移分离，迁移期间保留已有数据和可用结果，禁止把未完成的统计当成完整统计或把未回填当成零。完成后直接使用新字段，旧兼容路径只能服务明确的未迁移数据，并须有退出条件，禁止每次读取重新扫描、去重或清洗全部历史。
5、后台不等于低开销：清洗必须采用有界小批次、顺序推进、批间主动休息，限制记录数、字节数、单批执行时间和并发数；禁止一次加载全部历史、无界排队、每条数据启动任务或并行解密所有账号。慢 I/O/CPU 工作不得占用异步运行时线程；数据库使用短事务和短锁，遇到业务写入竞争时优先让路、延后重试，禁止长时间持有全局锁。
6、多个维护任务应共享资源预算或串行调度，避免启动/升级时同时扫描日志、回填账号和重算统计造成 CPU、内存、磁盘占用骤增。进度提交后释放批次内存；单条超大/异常数据也必须有处理边界，不能通过增加批次、延长超时或无限重试掩盖问题。迁移运行状态与失败原因应有可观测日志，正常成功无需弹框打扰用户。
7、回填必须避免覆盖新写入、复活已删除数据或重复累计；新增数据在写入时即符合新规则，历史扫描使用稳定游标/高水位，清空、重算、时区或算法版本变化必须同步失效相关派生数据。账号身份归并必须保留平台/租户边界和冲突规则，先安全保存结果再处理旧记录，失败时不得丢失账号。
8、精确 ID 与自由文本搜索必须分开：下拉选择和上下文跳转使用等值查询及对应索引，只有文本搜索使用模糊匹配；分页、增量解析和统计优先使用稳定游标、可恢复检查点及增量汇总，禁止名称为“增量”但每次从头解析全部已处理内容。
9、验证必须覆盖旧数据首次升级、重复启动/并发触发、迁移中新增/更新/删除、批次中断恢复、锁竞争、大数据量和超大单条记录；验证新旧结果语义一致、已完成迁移不重复执行、高频查询实际使用目标字段/索引，并记录批次/内存边界。未经明确授权仍不得操作真实用户数据或通过 GUI 测试。

本规范同时适用于 SQL、JSON 账号索引、文件日志解析和内存缓存。AGENTS.md 中保留同一规范；此文档用于版本管理与团队评审。
