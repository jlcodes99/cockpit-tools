# Codex 可见性修复中的项目与归属恢复

继续使用「会话管理 → 修复可见性」现有的快速修复、完整修复。账号、实例和 API 服务启动预览中的入口复用同一个弹框，并默认选中当前实例；没有单独的本地项目选项或切号提示。

## 快速修复

修正可见性索引，同时依据当前项目数据库和 JSON 补齐本地项目、新旧 ID 映射及会话归属，更新主线程和已有本地目录记录。项目补齐不读取历史快照、不扫描聊天正文、不探测项目目录，也不复制整个数据库。

项目补齐有独立的短时间预算和记录数限制。快速备份包含 JSON 和准确的字段变更计划，可按字段撤销；只处理有明确依据的记录。元数据过大、数据库忙、并发变化或实例仍在运行时，保留已有数据，在原结果或启动进度中说明维护推迟，可退出目标实例后重试或使用完整修复。预览不写入数据。

纯切号在目标凭据写入后，只处理已停止实例的账号项目状态，随后可以从官方客户端入口手动启动。“切号并启动”、默认实例和多开实例仍使用统一启动事务，在会话维护前优先恢复项目状态。

## 桌面启动时的账号状态恢复

macOS、Windows 的统一桌面启动流程在目标实例停止后，按当前实例配置指定的凭据快照判断实际身份；该快照可能来自 `auth.json` 或系统凭据存储。这里只读取身份依据，不修改凭据，也不上传状态。

新版客户端会在存在账号隔离状态、但没有 OAuth 用户身份时，向前端发送空的持久化状态。对于未绑定 OAuth 的 API 服务或 API Key 实例，启动前会将官方账号状态归档暂存在同一全局状态文件中，使客户端继续读取已有引导标记和本地状态；切回 OAuth 时恢复对应账号归档。不会把未完成的引导改为已完成，云项目和账号私有偏好继续隔离。

账号状态准备不要求已存在项目数据库。项目补齐使用本实例数据库中可核验的记录。大量会话会使会话归属维护推迟，项目登记、顺序和旧新 ID 映射仍可先恢复，SQLite 中已有的会话归属继续保留。纯切号和桌面启动均复用账号状态准备；单独打开官方客户端会读取该实例已落盘的状态。

同一实例内切换 OAuth 账号、API Key 或 API 服务时，本地项目与会话归属共用当前实例的数据库记录。项目优先使用有效的旧新 ID 映射或原生项目 ID 匹配，允许多个不同项目使用相同目录；没有明确 ID 依据时，仅在目录能唯一确定项目的情况下补齐。保留待删除项目、云项目、远程会话及其他实例的边界。

## 完整修复

包含项目与归属补齐，并可结合有效目录和历史 JSON 快照恢复缺失信息；同时执行已有的 Provider/目录修复及会话索引修复。必须完全退出所选桌面实例后应用，仍可在运行时预览。原来的独立“修复会话索引”入口继续保留。

会话索引部分检查原始记录与祖先链，备份并清理已确认失效的派生索引，由客户端重建。历史文件较多时会较慢，因此这部分仅进入完整修复和独立索引修复，不进入快速修复或自动启动。

## 数据边界与恢复

- 支持 macOS 路径和 Windows 盘符、UNC、长路径前缀；项目 ID 不按路径处理，POSIX 路径保留大小写及反斜杠语义。
- 保留明确无项目的会话、较新的归属和删除记录；排除云项目、子 Agent、guardian 和无法唯一判断的归属。完整恢复会跳过不可用的项目目录。
- 项目补齐本身不读取账号凭据文件；桌面启动时的身份读取范围见上文。不修改账号、聊天正文、归档状态或聊天更新时间，不上传修复数据。Provider 的调整仍由原有可见性修复负责；项目恢复本身不改 Provider，也不提供跨账号云项目同步或加密历史转换。
- 完整项目恢复在宿主统一备份目录创建 JSON、相关 SQLite 一致性备份和 `project-recovery-plan.json`；快速恢复保留 JSON 与字段变更计划。结果返回实际备份目录。
- 写入前保存 `.cockpit-local-project-recovery.json` 中断标记。写入失败按计划撤销；进程中断后，退出目标实例并执行完整修复，会先恢复未完成写入。快速修复保留中断计划并推迟相关项目维护。
- 回滚只恢复仍等于本次写入结果的字段或记录，保留后来新增的聊天及较新归属，不用旧 SQLite 文件覆盖当前历史。各实例、Provider 修复、项目恢复和索引修复分阶段提交；后续阶段失败时，错误保留已完成阶段的备份信息，便于重试。

## Windows 独立恢复脚本（PR #2955）

该 Python 标准库脚本保留原 PR 在 Windows 上验证的手动恢复入口。当前宿主的日常修复使用上文的内置流程；脚本适用于需要独立审计与恢复的 Windows 本地项目数据。

## 场景

`state_5.sqlite.projects` 仍存在项目，而 `.codex-global-state.json.local-projects`、旧新项目 ID 映射、显式会话归属缺失；普通 provider/路径可见性修复后，侧栏仍无项目。

## 运行

只读预览（可在 Codex 运行时执行）：

```powershell
python scripts/repair_codex_local_projects.py
```

完全退出 Codex 后应用（运行中会拒绝写入）：

```powershell
python scripts/repair_codex_local_projects.py --apply
```

应用前备份 JSON 和 SQLite 在线备份到 `CODEX_HOME/backups/local-project-visibility-时间戳`；备份路径会打印。使用 `--codex-home` 显式指定非默认数据目录，默认 `~/.codex`。

完全退出 Codex 后回滚：

```powershell
python scripts/repair_codex_local_projects.py --rollback "备份目录"
```

回滚只在字段仍等于本次写入值时恢复原值，不用旧数据库覆盖后来生成的新会话。

## 保护边界

- 不读取/改动 auth.json、API Key、OAuth、浏览器登录信息、模型 provider 或账号身份。
- 不恢复其他账号的云项目；当前缓存里的云项目不改归属。
- 只恢复数据库中存在且本地目录有效的独立项目，尊重待删除项目和明确的 projectless 会话。
- 恢复旧 ID 映射，避免生成重复项目；新旧 SQLite 会话归属与本地目录投影同步。
- 不改会话正文、rollout 文件、归档状态、来源类型、创建者或更新时间；不把 guardian/子 agent 放到侧栏。
- 同一数据目录里的独立本地项目不增加账号绑定；不同 CODEX_HOME/独立多开实例不是同一份历史。
- 不承诺跨账号云项目同步，也不重写 encrypted_content 以绕过原上下文限制。
